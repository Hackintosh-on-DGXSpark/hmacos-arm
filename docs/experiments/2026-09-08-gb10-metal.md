# Guest Metal on NVIDIA GB10

Date: 2026-09-08. All VM execution and NVIDIA tests ran on `dsec-dgx-spark`.

The Xvfb commands below preserve the historical experiment, not the current
launch workflow. Current scripts use [the physical desktop](../physical-desktop.md)
and can optionally mirror that same screen to the Mac.

## Result

**A deterministic Metal compute/readback workload inside arm64 Ventura passed
through Reims and physical NVIDIA GB10 Vulkan.** This is a bounded correctness
result, not a claim of complete graphics compatibility or production readiness.

The path is guest Metal -> Apple's AppleParavirtGPU driver -> QEMU
`reims-vgpu-mmio` -> Reims / metal2vulkan -> NVIDIA Vulkan. This reuses Reims,
including its command decoder and shader translator. It is not VFIO passthrough
and installs no NVIDIA driver or custom GPU kext in macOS.

| Check | Observed result |
| --- | --- |
| Host Vulkan compute | GB10 selected; 65,536 uint32 results correct; exit 0 |
| Host imported-memory compute | GPU read/write of 16 KiB-aligned host memory; exit 0 |
| Host Xlib presentation | NVIDIA vkcube, 30 frames on private Xvfb; exit 0 |
| `hw-01` | Login and desktop reached with NVIDIA; first Metal probe found no default device |
| `hw-02`, default selection | Default device nil, but `MTLCopyAllDevices()` returned one Apple Paravirtual device |
| `hw-02`, explicit negative control | One deliberately incorrect expected value detected; exactly one mismatch; exit 1 |
| `hw-02`, explicit correctness | Two different input seeds, 65,536 uint32 results each, zero mismatches; exit 0 |

The user separately confirmed the preceding Lavapipe software desktop worked.

## Evidence

Reims enumerated exactly one Vulkan candidate in `hw-02`:

```text
name="NVIDIA GB10" type=INTEGRATED_GPU
driver_id=NVIDIA_PROPRIETARY driver_info="580.159.03"
vendor_id=0x10de device_id=0x2e12
```

The launcher selected only `/usr/share/vulkan/icd.d/nvidia_icd.json`.
`nvidia-smi` identified the exact QEMU process, PID 164578, as `C+G`, with
262 MiB attributed to it at the recorded observation. Utilization after the
short workload was 0%; that idle sample is not a performance measurement.

The matching Reims interval at approximately `t=969381` ms recorded:

```text
compute_pipeline_misses=1 compute_pipeline_hits=2 dispatches=3
readbacks=3 readback_bytes=786432 fence_timeouts=0
compute_us=39 compute_n=3
```

Three dispatches and 3 x 262,144 bytes of readback match the one-round negative
control followed by the two-round correctness test. GPU timestamp spans are
supporting execution evidence, not a benchmark.

Recovered guest output:

```text
default_device=none enumerated_devices=1
enumerated_device=Apple Paravirtual device
selection=explicit-paravirtual-device
first_mismatch index=32768 expected=1fee8ac1 actual=1fee8ac0
round=0 seed=a5a5a5a5 checksum=0000805bc0588000 mismatches=1
negative_exit=1

round=0 seed=a5a5a5a5 checksum=0000805bc0588000 mismatches=0
round=1 seed=13579bdf checksum=00007f81c0588000 mismatches=0
PASS: guest Metal compute/readback; 2 x 65536 uint32 results verified
positive_exit=0
```

The shader reads an input buffer and writes a separate output buffer initialized
to a sentinel. The CPU computes the oracle independently. Inputs change between
rounds while buffers are reused, exercising visibility as well as arithmetic.
The negative control changes only one expected result, not the shader.

In the guest Terminal, using X11 input rather than relying on guest SSH:

```sh

```

The script runs the negative control and positive test with
`--explicit-device`. Without that flag, the probe preserves the observed
default-device failure rather than silently hiding it.

## Remaining limitations

- `MTLCreateSystemDefaultDevice()` still returns nil. Explicitly selecting the
  sole enumerated Apple paravirtual device works. Apps relying only on the
  default API may fail; the underlying default-selection cause is unresolved.
- Login wallpaper showed block-like artifacts. Logs include unsupported linear
  render-target formats and type-11 texture staging declines during desktop
  work. Linear-target creation falls back to an optimal GPU image in the source;
  it is not a switch to CPU rendering. These issues were not fixed here.
- Guest `system_profiler SPDisplaysDataType` produced no display section in the
  diagnostic log, while IOKit exposed AppleParavirtGPU, its Metal plugin, and
  active Metal clients including WindowServer and Terminal.
- This tests integer compute and shared-buffer readback, not broad Metal API
  coverage, graphics correctness, sustained performance, SMP, or stability.
- The guest clock is offset from the host. Host timestamps and Reims monotonic
  time identify runs; guest wall-clock text must not be used to align samples.

## Safety and cleanup

The baseline's `STAGING_COMPLETE` marker and all five `SHA256SUMS` checks passed
before testing and again afterward. Only disposable disk/AUX copies were booted.
No host kernel, firmware, driver, GPU binding, group membership, or persistent
security policy changed. No guest SIP/AMFI relaxation was made.

`hw-01` ended at its bound (exit 124 after 1202.49 seconds). For `hw-02`, guest
powerdown was requested, but QMP still reported running after 15 seconds; QMP
quit then stopped the experiment. This was not a verified clean guest shutdown.
The launcher reported exit 0 after 1511.79 seconds. The test volume had already
been synced and ejected. Experimental Xvfb servers were bounded and cleaned up
separately; the user's original TigerVNC 5901 session was preserved. Final checks
showed GB10 idle and no experimental GDB, guest-SSH-forward, or VNC listeners.
